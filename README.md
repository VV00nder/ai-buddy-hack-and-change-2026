# AI-buddy — ИИ-наставник для стажёров

**Команда «Нейрослопики»**, Hack&Change 2026, кейс Авито «AI-buddy: ИИ-наставник для стажёров».

AI-buddy помогает стажёру освоиться в команде: отвечает на рабочие вопросы по инструкциям со ссылкой на источник, ведёт по плану адаптации из чек-листа Авито и сам готовит заявки в корпоративных сервисах — стажёру остаётся проверить и нажать «Отправить». Наставник получает только те вопросы, на которые в инструкциях нет ответа, а его ответ становится частью базы знаний команды.

> **Видеодемонстрация:** [`docs/demo/ai-buddy-demo.mp4`](docs/demo/ai-buddy-demo.mp4) — путь от запроса до результата.
> **Презентация:** [`docs/presentation/AI-buddy.pdf`](docs/presentation/AI-buddy.pdf), [сценарий защиты](docs/presentation/demo-script.md), [ответы на вопросы](docs/presentation/qa-prep.md).

## Что умеет

| Сценарий | Стажёр | Наставник / руководитель |
|---|---|---|
| Ответы о команде и инструментах | Вопрос своими словами — короткий ответ и ссылка на раздел инструкции | — |
| План адаптации | День, этап, прогресс, просрочки, следующий шаг; шаги закрываются сами после выданных доступов | Прогресс своих стажёров, отметка своих шагов |
| Отгул (пример из кейса) | Объяснение порядка, проверка правил, черновик заявки, статус и комментарий руководителя | Согласование в один клик |
| Доступы | Нужный набор с персональными статусами; заявка с проектом, уровнем прав и обоснованием; понятный отказ для запрещённого роли | Согласует тот, кто отвечает за ресурс: владелец проекта, руководитель или DevOps |
| Цели стажировки | Измеримые цели с критерием успеха и сроком, отметка прогресса | Руководитель или наставник ставит цели и видит прогресс |
| Напоминания (ИИ-крон) | Утренняя сводка: день, этап, просрочки, следующий шаг | Напоминания о заявках и вопросах, которые ждут больше суток |
| Вопрос наставнику | Если ответа нет — вопрос из карточки, ответ приходит в чат | Входящие вопросы, ответ с сохранением в базу знаний |
| Метрики пользы | — | Доля вопросов без наставника, сэкономленные часы, оценки ответов |
| Приложение на телефоне | Устанавливается как приложение (PWA): иконка, ярлыки «Мой план» и «Заявки», открывается без сети | То же |

Чтобы установить на телефон, откройте адрес стенда в Chrome или Safari и выберите «Установить приложение» («На экран „Домой“»). Установка с телефона работает по HTTPS или с `localhost`.

Действия выполняются через корпоративные сервисы по **MCP** (в прототипе — имитация отсутствий, доступов и справочника). Права проверяет каждый сервис по токену пользователя.

## Быстрый старт (Docker)

Нужен Docker Desktop (Windows/macOS) или Docker Engine 24+ с Compose v2.

```bash
git clone https://github.com/VV00nder/ai-buddy-hack-and-change-2026.git
cd ai-buddy-hack-and-change-2026
docker compose up --build
```

В Windows можно просто дважды щёлкнуть `start-docker.bat`: он запустит то же самое в фоне и запишет вывод в `docker-run.log`.

Первая сборка — 3–6 минут (проверено на Windows 11 + Docker Desktop). Откройте **http://localhost:8080** и войдите в один клик тестовой учётной записью. Файл `.env` не обязателен: без ключа LLM ассистент работает в офлайн-режиме, все сценарии доступны.

Остановить: `Ctrl+C`, затем `docker compose down` (с удалением данных — `docker compose down -v`).

## Порядок проверки (10 минут)

1. **Анна.** Нажмите подсказку «Мне нужен отгул — как оформить и стоит ли писать руководителю?». Ответ из инструкции со ссылкой и подсказка с ближайшей допустимой датой.
2. Нажмите «Оформи отгул на …». Появится черновик-стикер: даты, кто согласует, остаток отгулов. Измените причину и нажмите **«Отправить заявку»** — на стикере штамп «На согласовании».
3. Напишите «Запроси доступ к stash на запись». Ассистент спросит проект — выберите `search-api`: в черновике проект, уровень «редактирование» и согласующий — владелец проекта Олег. Отправьте. Затем «Дай доступ к kubernetes» — отказ с объяснением и предложением staging.
4. Напишите «Где посмотреть тестовый стенд поиска?» — ассистент не нашёл ответа и предлагает вопрос наставнику. Отправьте.
5. Откройте «Мой план»: цели стажировки с критериями успеха, день, этапы, следующий шаг; кнопка «Спросить buddy» у шага.
6. **Выйти → Мария.** «Согласования»: согласуйте отгул с комментарием. Заявки на Stash у Марии нет — её согласует владелец проекта. В «Стажёры» → Анна можно добавить цель.
7. **Выйти → Олег.** «Согласования»: доступ к Stash. «Вопросы стажёров»: ответьте, оставив галочку «Сохранить в базу знаний».
8. **Выйти → Анна.** Колокольчик: статусы и комментарий. В чате — ответ наставника. В плане шаг «Получи доступ к Stash» закрыт автоматически. Спросите «Где тестовый стенд поиска?» — теперь ответ приходит сразу.
9. **Мария → «Польза»:** доля вопросов без наставника, сэкономленные часы.
10. **ИИ-крон:** утренние сводки и напоминания запускаются раз в час или вызовом
    ```bash
    curl -X POST localhost:8080/api/cron/reminders -H "X-Cron-Token: demo-cron"
    ```
    У Анны в чате появится «Напоминание AI-buddy» со следующим шагом.
11. **Обработка сбоев:** выключите сервисы и отправьте заявку — черновик сохранится, интерфейс покажет понятную ошибку:
    ```bash
    curl -X POST localhost:8090/admin/outage -H "X-Admin-Token: demo-admin" -d "{\"enabled\":true}"
    ```
    Включить обратно — `"enabled":false`.

Этот же сценарий автоматизирован: `e2e/demo.mjs` (17 проверок, см. «Тесты»).

## Языковая модель (внешний API)

| Параметр | Значение |
|---|---|
| Сервис | Любой OpenAI-совместимый Chat Completions API с tool calling: OpenAI, OpenRouter, vLLM, Ollama, шлюзы к YandexGPT/GigaChat |
| Модель по умолчанию | `gpt-4o-mini` (`LLM_MODEL`) |
| Ключ | переменная окружения `LLM_API_KEY` |
| Адрес | `LLM_BASE_URL` (по умолчанию `https://api.openai.com/v1`) |

```bash
cp .env.example .env      # впишите LLM_API_KEY, при необходимости LLM_BASE_URL и LLM_MODEL
docker compose up --build
```

Без ключа (или если модель недоступна) работает **офлайн-агент**: тот же набор инструментов и прав, детерминированная маршрутизация намерений. Текущий режим показан под полем ввода и в `GET /api/config`. Пример конфигурации без секретов — [`.env.example`](.env.example).

## Архитектура

```
Браузер (React + TS, TanStack Query, Zustand, Zod)
   │ REST + SSE
buddy (Go) ── сессии, агент, план, заявки, вопросы, метрики ── PostgreSQL, Redis
   │ MCP (JSON-RPC, токен пользователя)          └─ LLM (опционально)
corp-mock (Go) ── SSO, справочник, отсутствия, доступы
```

Стек соответствует стеку Авито: **Go**, **PostgreSQL**, **Redis**, **React + TypeScript + TanStack Query + Zustand + Zod**, Docker, метрики Prometheus для Grafana, события в формате clickstream, feature flags. Подробнее: [архитектура](docs/architecture.md), [внедрение в Авито](docs/integration.md), [безопасность](docs/security.md), [метрики и эксперимент](docs/metrics.md), [API](docs/api.md), [путь стажёра](docs/user-journey.md).

## Запуск без Docker

Нужны Go 1.24+ и Node.js 22+. Без `DATABASE_URL` и `REDIS_URL` данные хранятся в памяти.

```bash
cd web
npm install
npm run build
cd ../backend
go run ./cmd/corpmock          # терминал 1, порт 8090
go run ./cmd/buddy             # терминал 2, порт 8080 (WEB_DIR=../web/dist по умолчанию)
```

В Windows PowerShell выполняйте команды по одной строке.

## Тесты и покрытие

```bash
docker compose --profile test run --rm tests      # всё в Docker, с PostgreSQL и Redis
```
или локально:

## Тестовые данные и имитации

- Сотрудники, команды, баланс отгулов, каталог доступов — [`backend/internal/corp/fixtures/directory.json`](backend/internal/corp/fixtures/directory.json).
- Инструкции базы знаний — [`backend/internal/knowledge/docs`](backend/internal/knowledge/docs). Все помечены как тестовые и не являются регламентами Авито.
- План адаптации по чек-листу стажёра Авито — [`backend/internal/onboarding/template.json`](backend/internal/onboarding/template.json).
- Имитация корпоративных сервисов — `corp-mock`: MCP на `:8090/mcp`, SSO на `:8090/sso/token`.

Все данные синтетические. Дата начала стажировки считается от текущей даты, поэтому демо всегда «живое».

## Границы прототипа

- Производственный календарь упрощён (только выходные).
