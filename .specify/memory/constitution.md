# Конституция AI-buddy

Неизменяемые принципы, по которым писались спецификации, код и тесты. Каждая фича в `specs/` проверяется на соответствие этим пунктам.

## I. Помощник, а не замена наставника
AI-buddy снимает рутину: организационные вопросы, поиск инструкций, оформление заявок. Содержательные вопросы о задачах, коде и развитии он направляет наставнику. Если ответа нет в источниках, ассистент говорит об этом и предлагает передать вопрос наставнику.

## II. Только проверяемые факты
Ответы строятся на базе знаний команды и ответах корпоративных сервисов. В каждом ответе из базы знаний есть ссылка на раздел-источник. Ассистент не придумывает правила, сроки, ссылки и имена. Все инструкции прототипа помечены как тестовые и не выдаются за регламенты Авито.

## III. Действия — только после подтверждения человеком
Любое действие с побочным эффектом (заявка на отсутствие, доступ, вопрос наставнику) сначала проверяется сервисом в режиме `dry_run` и показывается стажёру карточкой-черновиком. Отправка происходит только по кнопке. LLM не может отправить заявку сам.

## IV. Права проверяются в сервисах, а не в промпте
Права пользователя (роль, команда, наставник, руководитель) проверяются на трёх уровнях: фильтр базы знаний до LLM, список MCP-инструментов по роли и повторная проверка в каждом корпоративном сервисе. Попытка prompt injection не даёт доступа к закрытым данным или операциям.

## V. Интерфейс никогда не ждёт модель
Локальные операции укладываются в 1 секунду. Обращение к LLM и сервисам выполняется асинхронно: интерфейс сразу показывает, что ответ готовится, и шаги работы агента. Сбой модели переключает ответ на офлайн-режим, сбой сервиса сохраняет черновик для повторной отправки.

## VI. Встраивается в инфраструктуру Авито, а не дублирует её
Авторизация, данные сотрудников и ролевая модель берутся из существующих систем (в прототипе — их имитации). Корпоративные сервисы подключаются по MCP, поведение агента описано спецификацией, функции включаются feature flags, события пишутся в формате, совместимом с clickstream. Стек: Go, PostgreSQL, Redis, React + TypeScript + TanStack Query + Zustand + Zod.

## VII. Синтетические данные и минимум персональных данных
Только синтетические сотрудники и инструкции. Больничные, зарплата и финансовые операции вне области задачи. В логах и событиях нет текста сообщений, только типы событий и технические признаки.

## VIII. Тесты — часть спецификации
У каждого критерия приёмки есть автоматический тест. Покрытие строк прикладного кода больше 80% (бэкенд и фронтенд считаются отдельно). Сквозной сценарий проверяется e2e-скриптом, который также записывает видеодемонстрацию.
