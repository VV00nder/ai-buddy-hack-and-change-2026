# 004. Доступы через систему доступов

По ответу экспертов Авито: заявка включает **проект**, **обоснование** и **уровень прав** (чтение, редактирование, администрирование); **согласующий зависит от типа ресурса** — владелец проекта, руководитель, DevOps или другой ответственный.

| Система | Согласует | Особенности |
|---|---|---|
| VPN, Jira, Confluence команды, Tech-dep, Grafana, Sentry | автоматически | — |
| Stash: репозиторий | владелец проекта | нужен проект; администрирование стажёрам — только исключением руководителя |
| Confluence кластера, Redash | руководитель | Redash — с обоснованием |
| Kubernetes: staging | дежурный DevOps | с обоснованием |
| Kubernetes: прод | руководитель (исключение) | по правилам стажёрам недоступно, предлагается staging; с обоснованием заявка уходит руководителю на пересмотр |

## Пользовательские истории
- **Стажёр** спрашивает «какие доступы мне нужны» и получает базовый набор первой недели и свои текущие статусы: что есть, что ждёт согласования, что можно запросить.
- **Стажёр** просит «запроси доступ к Stash на запись» — AI-buddy проверяет каталог и готовит заявку; автоматические доступы выдаются сразу, остальные согласует руководитель.
- **Стажёр** просит недоступное роли (продовый Kubernetes) — получает объяснение и альтернативу, без черновика.

## Критерии приёмки
| # | Дано | Когда | Тогда | Тест |
|---|---|---|---|---|
| 1 | Каталог из 10 систем | «Какие доступы мне нужны?» | Базовый набор и персональные статусы; запрещённые роли системы не предлагаются | `TestOfflineAccessScenario` |
| 2 | Stash требует проекта | «Запроси доступ к stash на запись» | Вопрос о проекте с подсказками проектов команды; после ответа «search-api» — черновик `edit`, согласует владелец проекта Олег | `TestOfflineAccessScenario` |
| 2a | Владелец проекта — наставник | Руководитель пытается согласовать | 403; заявка видна только владельцу | `TestAccessAutoCompletesPlan` |
| 2b | Kubernetes: staging | Заявка с обоснованием | Согласует дежурный DevOps, у него есть раздел «Согласования» | `TestDevopsApproval` |
| 2c | Уровень «администрирование» для стажёра | Запрос | Объяснение правил и разрешённых уровней; с обоснованием — заявка руководителю с отметкой «вне правил» | `TestOfflineAccessScenario`, `TestAccessException` |
| 3 | Канал Tech-dep выдаётся автоматически | Стажёр отправляет | Статус «Выдан», шаг плана закрыт | `TestAccessAutoCompletesPlan` |
| 4 | Kubernetes prod запрещён стажёрам | Запрос | Объяснение «используй staging через LENS» и предложение написать обоснование; черновика нет. Следующий вопрос («Где стенд?») не считается обоснованием | `TestOfflineAccessScenario`, `TestAccessException` |
| 4а | Заявка вне правил с обоснованием | Отправка | Согласует руководитель стажёра; в кабинете — «вне правил» и «Сделать исключение» | `TestAccessException`, `TestLeadDashboard` |
| 5 | Redash требует обоснования | Запрос без обоснования | Ассистент просит обоснование и принимает его следующим сообщением | `TestOfflineAccessScenario` |
| 6 | Доступ уже выдан / заявка уже ждёт | Повторный запрос | Сообщение о дубле | `TestAccess`, `TestOfflineAccessScenario` |
| 7 | Черновик | Стажёр пытается изменить поле `system` | 400: служебные поля не редактируются | `TestAccessAutoCompletesPlan` |
