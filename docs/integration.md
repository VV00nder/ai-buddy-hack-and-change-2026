# Внедрение в инфраструктуру Авито

Прототип собран так, чтобы его компоненты заменялись на существующие системы Авито без переписывания логики.

| В прототипе | В Авито | Что поменять |
|---|---|---|
| mock-SSO (`corp /sso/token`), HMAC-токен личности | Корпоративная авторизация и ролевая модель | Заменить `app.Login` на проверку корпоративного токена; токен пользователя по-прежнему передаётся сервисам (on-behalf-of) |
| Справочник из `fixtures/directory.json` | Данные сотрудников | MCP-сервер справочника поверх HR-данных: тот же контракт `directory_whoami`, `directory_team` |
| Имитация системы отсутствий | Система отсутствий | MCP-адаптер с теми же инструментами `absence_*` (включая `dry_run`) |
| Имитация системы доступов | Система заявок на доступы | MCP-адаптер `access_*` |
| Агент в коде AI-buddy | Платформа ИИ-агентов с промптами и MCP | Перенести промпт и правила из `specs/agent/agent-spec.md`, подключить те же MCP-серверы; guardrails (`dry_run`, подтверждение) остаются в сервисном слое AI-buddy |
| `FF_*` из переменных окружения | Feature flags (compile-time и runtime) | Читать флаги из сервиса флагов; точки проверки уже выделены (`app.applyFlags`, `submitCorp`, `submitQuestion`) |
| Таблица `events` + JSON-логи | Clickstream / Kafka | Добавить sink, публикующий `domain.Event` в Kafka; формат уже плоский: `type`, `userId`, `props`, `at` |
| `/metrics` в формате Prometheus | Grafana | Добавить scrape; готовы `buddy_events_total{type}` и гистограмма `buddy_agent_seconds` |
| `POST /api/cron/reminders` + встроенный таймер | Внутренний ИИ-крон | ИИ-крон по расписанию вызывает эндпоинт со служебным токеном `X-Cron-Token`; встроенный таймер отключается (`REMINDER_INTERVAL_MINUTES=0`) |
| Согласующие из `fixtures` (владельцы проектов, дежурный DevOps) | Система доступов, владельцы ресурсов | Согласующего определяет сервис доступов; AI-buddy только показывает его и напоминает о зависших заявках |
| Веб и PWA | Корпоративный мессенджер | Бот-адаптер как ещё один клиент API: входящие сообщения → `POST /api/messages`, обновления из `events.Hub` → уведомления в мессенджер |
| Docker Compose | Docker, CI/CD | Готовые образы `buddy` и `corpmock`, GitHub Actions как пример пайплайна |

## Как добавить новый сервис (например, командировки)
1. Реализовать MCP-сервер с инструментами `trip_policy`, `trip_create(dry_run)`, `trip_list`.
2. Указать его адрес AI-buddy — агент получит инструменты через `tools/list`.
3. Добавить тип действия, подпись в `toolLabels` и карточку в интерфейсе.
4. Описать сценарий в `specs/` и добавить строки в проверочный набор агента.

## Дальнейшее развитие
- Подключение реальных источников знаний (Confluence) с сохранением прав пространства.
- Проактивные подсказки: «завтра экватор — вот чек-лист» через ИИ-крон.
- Сценарии для наставника: черновик обратной связи по чек-листу, напоминания о 1:1.
- После онбординга AI-buddy остаётся точкой входа для рабочих вопросов.
- Бот в корпоративном мессенджере и push-уведомления PWA о статусах заявок — без изменений в агенте.
